There are four kinds of metadata that you should know about.

1. **Descriptive Metadata**: This is information that describes the content and context of your data.
  - Examples: title, creator, subject keywords, and description.
2. **Structural (Technical) Metadata**: This metadata describes the physical structure of the compound data that comprises the file or digital materials.
  - Examples: camera used, aperture, exposure, file format, and relation to other data or files.
3. **Adminstrative Metadata**: This information relates to how you manage your data.
  - Examples: When and how the data was created, who has access, software required to use the files, and copyright permissions.
4. **Preservation Metadata**: This is structured information that helps preserve and manage digital resources over time.
  - Examples: Original analog format, file format, provenance, fixity values, access rights, audit trail, encoding software, and resolution.

When we organize all of the metadata in our data, we often will want to follow a standardized set of metadata developed by other professionals. These are called metadata schemas, and they can help take the confusion out of the process of generating metadata, if we need to do so for our projects.

Some schemas are:
- Dublin Core
- MODS (Metadata Object Description Schema)
- OLAC (Open Language Archive Community)
- VRA (Visual Resources Association) Core
- TEI (Text Encoding Initiative)
- PREMIS (Preservation Metadata Implementation Strategies)

Sometimes you will need to generate your own metadata schema, because you do not need to follow a schema to the letter, or because you are working with a community that is only interested in certain kinds of metadata. These schemas can be good starting points for understanding how and why metadata is structured in particular ways.
