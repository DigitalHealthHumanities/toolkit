Oftentimes, when we start developing digital research projects, we may assume that the data we will generate will be easy to work with. We may assume that we can pull some addresses from a map, plug them into a platform like ArcGIS or QGIS, and produce a map, but when we start that project, we stumble into a taxing reality: **Producing data is time consuming**.

Digital archivists spend a great deal of time organizing their collections in ways that help facilitate researchers, helping reduce the time required to shape data into a computationally useful form. The digital materials you get from a digital archive, be it the [Industry Documents Library](https://www.industrydocuments.ucsf.edu/home/) or [HathiTrust](https://www.hathitrust.org/), has been processed in such a way as to have metadata that fits into the schemas that guide the structure of those sites. That metadata can be really useful for researchers too, because it allows you to search using the specific metadata categories. For example, if you are working on research pertaining to cigarette ads in the 1960’s, you can do a search for matching keywords—-like ‘advertisements’ and ‘cigarettes’—-in a date range—-1960 – 1969. Metadata enables those searches to happen.

When a digital archivist processes this data they may do all (or some) of the following procedures, some of which is used for creating a file’s metadata:

- Normalizing file names
- Migrating to standardized file formats
- Manually describing the files
- Private health information (PHI) and publicly identifiable information (PII) redaction
- Extracting technical metadata
- Preserving original file folder and directory
- Identifying named entities
- Tagging for key terms and topics
- Processing text through an optical character recognition (OCR) program
- Speech-to-text transcription

All of these processes either help structure the data, through standardized terms and names, or make it more computationally accessible, through the creation of machine readable text formats.
